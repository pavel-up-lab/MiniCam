# Продолжение растущего архивного файла

## Проблема

Камера публикует текущую непрерывную запись как растущий архивный файл. RTSP-адрес, открытый MiniCam, содержит время окончания, известное на момент запуска. Когда воспроизведение достигает этого времени, камера уже может сообщать более позднее окончание того же файла.

Текущая логика ищет только следующий элемент в обновлённом массиве архивных фрагментов. Если продолжение находится в том же обновлённом элементе, MiniCam считает, что следующего архива нет, и ошибочно переключается на прямой эфир.

## Желаемое поведение

- При окончании архивного RTSP-потока MiniCam запоминает достигнутое время и немедленно обновляет последние две минуты архива.
- Сначала приложение ищет фрагмент, который содержит достигнутое время и заканчивается позднее минимум на 0,5 секунды. Это считается продлённой версией текущего файла.
- Если такого фрагмента нет, приложение ищет следующий архивный фрагмент, начинающийся после достигнутого времени.
- Продлённый файл открывается с достигнутого времени плюс 0,001 секунды, чтобы не повторно завершиться на той же границе.
- Новый файл открывается с его начального времени.
- Если продолжение не найдено, выполняются ещё две попытки с паузой 0,5 секунды между ними.
- Только после трёх неудачных попыток приложение переходит в прямой эфир.

## Разделение ответственности

Небольшой чистый `ArchiveContinuationResolver` выбирает продолжение по времени окончания и текущему списку фрагментов. `AppContainer` отвечает за обновление данных, короткие повторные попытки и запуск выбранного архива. `VLCPlaybackController` по-прежнему только сообщает об окончании потока.

## Состояние интерфейса

Во время поиска продолжения транспорт временно помечается занятым. На экране остаётся последний кадр VLC; отдельные сообщения или новые элементы управления не добавляются. После запуска продолжения интерфейс снова становится доступным.

## Ошибки

Ошибки обновления не очищают известный архив. Каждая попытка повторно применяет выбор к имеющимся данным. После исчерпания попыток прямой эфир остаётся безопасным запасным вариантом.

## Проверки

Минимальные unit-тесты проверяют три невизуальных случая: выбор продлённого текущего файла, выбор нового следующего файла и отсутствие продолжения. После этого выполняются общие тесты и обычная сборка. Финальная проверка на камере подтверждает, что приложение не прыгает в эфир при росте текущего архивного файла.

## Вне объёма

- Восстановление физических разрывов в записи камеры.
- Изменение 15-секундного фонового обновления.
- Предварительное переподключение до достижения границы файла.
- Изменение таймлайна и кадров предпросмотра.

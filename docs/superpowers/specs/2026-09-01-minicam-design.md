# MiniCam — проектирование первой версии

Дата: 2026-09-01

## 1. Назначение

MiniCam решает одну задачу: даёт владельцу одной локальной камеры Hikvision быстрый прямой эфир и непрерывную навигацию по круглосуточному архиву на microSD в одном окне macOS. Приложение не создаёт второй архив и не требует сервера.

## 2. Критерии успеха

1. Прямой эфир использует тот же RTSP-поток и движок VLC, поэтому его задержка сопоставима с VLC.
2. Пользователь перетаскивает единую шкалу назад из прямого эфира и попадает в запись на microSD.
3. Пользователь перемещается вперёд и назад по доступной истории, включая переходы между файлами и сутками.
4. При достижении текущего времени или нажатии «В прямой эфир» приложение возвращается к live RTSP.
5. Приложение собирается как Universal binary для `x86_64` и `arm64` с deployment target macOS 12.
6. Учётные данные не попадают в исходный код, Git, UserDefaults или журналы.

## 3. Границы первой версии

Входит:

- одна камера Hikvision в локальной сети;
- настройка IP-адреса, HTTP-порта, RTSP-порта, канала и учётных данных;
- проверка подключения;
- прямой эфир;
- поиск архива на microSD по выбранному периоду;
- единая временная шкала эфир/архив;
- пауза, звук, полноэкранный режим и возврат в эфир;
- календарь для перехода к старой дате;
- автоматическое восстановление после краткого сетевого сбоя;
- безопасный локальный журнал.

Не входит:

- несколько камер;
- удалённый доступ через интернет;
- NVR или запись на диск Mac;
- аналитика и события;
- экспорт клипов;
- App Store, облачная синхронизация и подписки.

## 4. Совместимость

- macOS Monterey 12 и новее;
- Intel `x86_64` и Apple Silicon `arm64`;
- Universal `.app`;
- SwiftUI без API, появившихся после macOS 12;
- VLCKit стабильной ветки 3.x;
- предпочтительный видеокодек камеры — H.264;
- целевая камера для интеграционной проверки — Hikvision DS-2CD2043G2-IU по адресу `192.168.1.122`.

Версия VLCKit должна быть зафиксирована. Готовый framework или XCFramework обязан содержать обе архитектуры и включаться в приложение. Экспериментальная ветка VLC 4 не используется.

## 5. Архитектура

### MiniCamApp

Создаёт главное окно, корневое состояние и зависимости приложения.

### CameraProfile

Содержит несекретные настройки: адрес, HTTP- и RTSP-порты, номер канала. Имя пользователя и пароль передаются через отдельное хранилище учётных данных.

### CredentialStore

Читает и записывает учётные данные в Keychain. Пароль не передаётся в журналы и не включается в отображаемые URL.

### HikvisionClient

Выполняет Digest-авторизацию ISAPI, проверяет сведения об устройстве, состояние хранилища и ищет записи за заданный интервал. XML камеры преобразуется в типизированные модели домена.

### LiveStreamService

Строит URL основного или дополнительного RTSP-потока из профиля камеры и канала.

### ArchiveService

Запрашивает записи порциями, нормализует часовой пояс, сортирует интервалы и объединяет соседние технические фрагменты для отображения. Исходные интервалы сохраняются для точного открытия нужной записи. Результаты выбранных суток кэшируются в памяти.

### VLCPlayerAdapter

Изолирует VLCKit от остального приложения. Управляет запуском, паузой, остановкой, звуком, временем и состоянием загрузки. Параметры прямого эфира используют небольшой RTSP-буфер и аппаратное декодирование, когда оно доступно.

### PlaybackCoordinator

Представляет единый режим воспроизведения:

- `live` — прямой RTSP;
- `archive(timestamp)` — запись с microSD;
- `loading(target)` — переключение;
- `failed(message)` — восстанавливаемая ошибка.

Координатор выбирает архивный фрагмент по времени, переключает источник VLCKit, продолжает следующий фрагмент, пересекает границу суток и возвращает live при достижении текущего времени.

### SwiftUI UI

Отображает видео, состояние, элементы управления, календарь и единую временную шкалу. Обёртка `NSViewRepresentable` предоставляет VLCKit поверхность AppKit, совместимую с Monterey.

## 6. Поток данных

### Запуск

1. Приложение читает несекретный профиль и учётные данные из Keychain.
2. `HikvisionClient` проверяет HTTP/ISAPI.
3. `LiveStreamService` формирует RTSP-источник.
4. `PlaybackCoordinator` запускает live через `VLCPlayerAdapter`.
5. `ArchiveService` в фоне запрашивает интервалы текущих суток и строит шкалу.

### Переход назад

1. Пользователь перетаскивает указатель времени.
2. Во время перетаскивания интерфейс обновляет только предварительное время.
3. После отпускания `ArchiveService` выбирает содержащий время или ближайший следующий фрагмент.
4. Координатор переводит состояние в `loading`, открывает архивный источник и затем `archive(timestamp)`.

### Продолжение и возврат в эфир

По окончании фрагмента координатор открывает следующий доступный фрагмент. Если следующая запись относится к новым суткам, интервалы этих суток загружаются автоматически. Если архив достигает live edge, источник меняется на прямой RTSP и состояние становится `live`.

## 7. Временная шкала

Шкала представляет эфир и историю как одну ось времени. Правый край обозначает «Сейчас». Доступные интервалы записи визуально выделены, разрывы остаются заметными. Календарь перемещает видимую область к выбранным суткам, но не открывает отдельный экран архива.

При разрыве выбранное время переносится к ближайшей последующей записи. При небольшом техническом разрыве переход выполняется автоматически. Перетаскивание не создаёт запросы к камере до отпускания указателя.

## 8. Ошибки и восстановление

Пользователь получает отдельные сообщения для недоступной камеры, неверных учётных данных, недоступного RTSP, отсутствующей или неготовой microSD, пустого дня, несовместимого архива и сетевого разрыва.

При разрыве live выполняется ограниченное автоматическое переподключение. При разрыве архива приложение повторно открывает текущий фрагмент приблизительно с последней подтверждённой позиции. Если восстановление невозможно, текущая ошибка остаётся на экране, а кнопка «В прямой эфир» доступна.

## 9. Безопасность

- пароль хранится только в Keychain;
- профиль не содержит пароль;
- URL с учётными данными не журналируются;
- сообщения Digest-аутентификации не записываются полностью;
- внешние порты и удалённый доступ не требуются;
- приложение работает с камерой только в локальной сети.

## 10. Проверки

Автоматические тесты ограничены логикой, которую нельзя уверенно проверить визуально:

1. Разбор репрезентативного XML-ответа поиска Hikvision.
2. Нормализация, сортировка и объединение интервалов.
3. Выбор фрагмента для заданного времени и поведение в разрыве.
4. Переходы состояния `live → archive → live`.
5. Сериализация профиля без секретов.

Ручные интеграционные проверки на реальной камере:

- задержка live по сравнению с VLC;
- открытие разных точек архива;
- перемотка вперёд и назад;
- последовательный переход между фрагментами и сутками;
- возврат в эфир;
- восстановление после краткого сетевого разрыва;
- запуск Universal-сборки на Intel Mac с Monterey.

## 11. Ограничения и риски

- камера может тратить 1–3 секунды на открытие произвольного архивного фрагмента;
- конкретные ISAPI-возможности необходимо подтвердить на установленной прошивке;
- старый Intel GPU может не декодировать выбранный кодек аппаратно;
- сборка VLCKit должна быть проверена на обе архитектуры;
- часы камеры должны иметь правильный часовой пояс, иначе шкала будет смещена;
- абсолютная бесшовность на границе файлов не гарантируется камерой, но UI остаётся единым.

## 12. Условия завершения первой версии

Первая версия завершена, когда она собирается для обеих архитектур, подключается к целевой камере без секретов в проекте, показывает live с приемлемой задержкой, открывает запись из единой шкалы, перемещается по доступной истории и возвращается в прямой эфир.

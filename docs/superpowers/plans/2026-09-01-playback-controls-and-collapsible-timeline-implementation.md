# План реализации управления воспроизведением

## 1. Изолировать расчёт шагов

- Добавить чистый `ArchiveStepResolver`, который получает сегменты, текущее время, направление и величину шага.
- Для попадания в разрыв выбирать конец предыдущего сегмента при движении назад и начало следующего при движении вперёд.
- Ограничить переход началом архива и переводить результат у правой границы в прямой эфир.
- Проверить только эти граничные расчёты компактными модульными тестами.

## 2. Добавить состояние и команды плеера

- Расширить `VLCPlaybackController` опубликованным состоянием паузы.
- Добавить низкоуровневые операции паузы и продолжения архивного потока.
- Сбрасывать паузу при открытии эфира, нового архивного адреса и при ошибке.
- Не менять существующие параметры кэширования и плавности VLCKit.

## 3. Координировать команды в контейнере

- Добавить команды Play/Pause и шага по времени в `AppContainer`.
- При паузе эфира запоминать время, а при Play открывать архив с сохранённого момента.
- Для шага использовать единый `ArchiveStepResolver` и существующий запуск архива.
- Новый выбор времени и кнопка `В эфир` должны снимать паузу.

## 4. Добавить изолированные элементы интерфейса

- Создать `PlaybackControlsView` с кнопками `−30`, `−10`, Play/Pause, `+10`, `+30`.
- В `CameraPlayerView` добавить состояние раскрытия и стрелку в верхнюю строку.
- В раскрытом состоянии разместить компактные кнопки в одной строке со статусом, а ниже показать детальную и обзорную шкалы.
- В свёрнутом состоянии показать только узкую строку и неинтерактивный индикатор положения архива.
- Сохранить существующие цвета, кнопку `В эфир`, центральную линию и пометку о ключевом кадре.

## 5. Обновлять хвост архива во время эфира

- Запускать в `AppContainer` единственный цикл фонового обновления после включения прямого эфира.
- Каждые 15 секунд запрашивать свежий участок записей и заменять им пересекающийся устаревший хвост.
- Не изменять текущий поток, положение таймлайна или выбранное время при успешном обновлении.
- Останавливать цикл на паузе, в архиве и при ошибке; запускать заново после возврата в эфир.
- Сохранять текущие данные и продолжать цикл после временной ошибки камеры.

## 6. Проверить результат

- Запустить только существующие важные тесты и новые тесты расчёта шагов.
- Собрать Debug и открыть приложение с реальной камерой.
- Вручную проверить раскрытие, сворачивание, паузу эфира с продолжением из архива и четыре шага.
- Убедиться, что во время эфира правая граница доступного архива обновляется примерно каждые 15 секунд без прерывания видео.
- После подтверждения собрать Universal Release для `arm64` и `x86_64` с macOS 12.0.

# План реализации настроек событий движения

## 1. Расширить модель настроек

- Добавить в `MiniCam/Domain/AppSettings.swift` тип режима событий с вариантами «Только люди» и «Люди и транспорт».
- Добавить допустимый срок хранения 1, 3 или 7 дней и дату последней плановой очистки.
- Сделать декодирование обратно совместимым: старые данные получают режим «Люди и транспорт», 3 дня и текущую дату отсчёта без очистки.
- При первом обновлении старых настроек сохранить заполненные значения, чтобы дата отсчёта не создавалась заново при каждом запуске.

## 2. Отделить хранение от политики очистки

- В `MiniCam/Infrastructure/MotionEventStore.swift` убрать автоматическое удаление из обычных `save` и `load`.
- Добавить явную плановую очистку событий старше переданной даты.
- Добавить полную очистку JSON-метаданных и связанных JPEG внутри `MotionEvents`.
- После каждой операции возвращать фактически сохранённый список, чтобы интерфейс совпадал с содержимым диска.
- Не удалять никакие файлы за пределами каталога событий.

## 3. Применить фильтр до трекера

- В `ArchiveMotionAnalyzer` хранить активный режим событий.
- Перед каждым вызовом `MotionEventTracker.process` оставлять только разрешённые категории.
- При смене режима сбрасывать трекер и предыдущий кадр, не изменяя опубликованную историю.
- Добавить безопасные операции плановой и полной очистки: приостановить текущий анализ, дождаться завершения активной работы с хранилищем, выполнить удаление, перечитать список и возобновить анализ.

## 4. Запустить ежедневную проверку

- В `AppContainer` добавить одну управляемую задачу очистки с периодом 24 часа от сохранённой даты последней успешной проверки.
- Если дата отсутствует после обновления, записать текущий момент и запланировать первую проверку через 24 часа.
- Если приложение было закрыто до срока, выполнить проверку при первом последующем запуске после истечения 24 часов.
- После успешной плановой очистки сохранить новую дату. После ошибки оставить дату прежней для повторной попытки без удаления других данных.
- При сохранении нового срока не запускать очистку немедленно.

## 5. Обновить применение настроек

- Расширить `AppContainer.applySettings` режимом событий и сроком хранения.
- Сначала сохранить полностью подготовленные настройки, затем применить их к анализатору.
- Добавить опубликованное состояние ручной очистки и метод её запуска для формы.
- Сохранять прежнюю дату плановой проверки при обычном редактировании формы.

## 6. Обновить центральную форму

- В `SettingsPanel` заменить отдельную строку распознавания единым компактным разделом `СОБЫТИЯ ДВИЖЕНИЯ` по выбранному варианту B.
- Оставить существующий переключатель, добавить поля «Тип событий» и «Хранить историю».
- Отключать только выбор типа при выключенном распознавании.
- Добавить красную кнопку полной очистки и подтверждение поверх формы.
- Во время очистки блокировать закрытие и повторное действие; после успеха оставить форму открытой и показать «История очищена».
- Ошибку показывать внутри формы без сброса черновика остальных настроек.

## 7. Выполнить минимальные проверки

- Обновить `AppSettingsStoreTests`: загрузка старого формата и сохранение новых значений.
- Проверить доменную фильтрацию: режим «Только люди» исключает все транспортные категории.
- Обновить `MotionEventStoreTests`: плановая очистка по переданной границе удаляет только просроченные JSON/JPEG.
- Добавить проверку полной очистки, включая сохранение постороннего файла вне `MotionEvents`.
- Не добавлять тесты визуальной компоновки SwiftUI.

## 8. Проверить форму и собрать приложение

- Собрать Debug и открыть существующее приложение на реальной камере.
- Вручную проверить оба режима, недоступность поля типа, сохранение 1/3/7 дней, подтверждение и успешную очистку.
- Убедиться, что очистка не прерывает прямой эфир и новые события после неё снова появляются.
- Обновить README.
- Собрать и локально подписать Universal Release для `arm64` и `x86_64`, проверить минимальную macOS 12 и встроенные ресурсы.

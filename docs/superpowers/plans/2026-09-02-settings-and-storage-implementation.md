# План реализации настроек и внешнего хранения

## 1. Добавить модель настроек приложения

- Создать `AppSettings` с двумя параметрами первой версии: `isMotionTrackingEnabled` и сохранённым доступом к внешней папке.
- Трекинг по умолчанию включён; отсутствие внешней папки означает стандартный корень `Application Support/MiniCam`.
- Создать отдельный `AppSettingsStore` поверх `UserDefaults`, не расширять `ProfileStore` настройками, не относящимися к камере.
- Хранить security-scoped bookmark и отображаемый путь. При чтении повреждённого bookmark сохранять внутреннее хранилище рабочим.
- Одной проверкой подтвердить значения по умолчанию и сохранение/восстановление обоих параметров.

## 2. Ввести единый выбор активного корня

- Создать `StorageRootResolver`, который знает внутренний корень, предпочтительную внешнюю папку и фактически активный корень.
- Описать состояния: внутреннее хранение, внешнее хранение, внутренний резерв при недоступной внешней папке, перенос, ожидание повторного переноса.
- Проверять существование папки и пробную запись небольшого временного файла до признания внешней папки доступной.
- Удерживать security-scoped доступ к внешней папке, пока она выбрана и доступна; освобождать его при смене папки.
- Не хранить настройки, состояние интерфейса и файловую миграцию внутри `FrameCacheStore` или `MotionEventStore`.

## 3. Сделать оба хранилища переключаемыми

- Передавать `StorageRootResolver` в `FrameCacheStore` и `MotionEventStore`.
- Определять активную директорию перед каждой файловой операцией.
- В `FrameCacheStore` сбрасывать и заново загружать индекс при смене корня, сохраняя существующий формат имён по миллисекундам.
- В `MotionEventStore` строить URL JSON и JPEG относительно текущего корня, сохраняя существующие UUID и трёхдневное удаление.
- Оставить форматы файлов совместимыми с уже накопленными данными, чтобы перенос не требовал преобразования.

## 4. Реализовать безопасное объединение данных

- Создать отдельный `StorageMigrationService`, который переносит `FrameCache/v2-720p` и `MotionEvents` между корнями.
- До начала копирования направлять новые записи в выбранный безопасный активный корень.
- Копировать отсутствующие файлы, проверять размер результата и только после проверки удалять источник.
- При совпадении имён не перезаписывать корректный файл вслепую: сравнивать размер, сохранять подтверждённую копию и удалять дубль только после проверки.
- Повторять проход по источнику, пока там не останется новых файлов, появившихся во время переноса.
- При ошибке прекращать удаление, сохранять доступные копии и публиковать состояние ожидания повтора.
- Одной файловой проверкой охватить перенос обоих подкаталогов, конфликт имени и отсутствие удаления при ошибке проверки.

## 5. Подключить резерв и автоматическое восстановление

- Создать `StorageCoordinator`, объединяющий resolver, migration service и публикуемое состояние для интерфейса.
- При запуске разрешать сохранённую внешнюю папку. Если она недоступна, немедленно выбирать внутренний корень.
- Проверять предпочтительную внешнюю папку при штатном пятнадцатисекундном обновлении архива, без отдельного частого таймера.
- После возвращения папки переключать новые записи наружу и последовательно объединять внутренний резерв с внешними данными.
- При выборе новой внешней папки переносить доступные данные из прежней внешней папки и внутреннего резерва.
- При возврате к внутреннему хранению переносить доступные внешние данные внутрь.
- Проверкой на временных папках подтвердить переход на внутренний резерв и автоматическое объединение после восстановления.

## 6. Отделить сбор кадров от распознавания

- Добавить в `ArchiveMotionAnalyzer` изменяемую настройку трекинга.
- При выключении продолжать `ArchiveFrameSampler` и запись JPEG в `FrameCacheStore`, но пропускать Core ML, `MotionEventTracker` и создание `MotionEvent`.
- При выключении сбрасывать текущие треки. При повторном включении ставить новый временной порог и анализировать только кадры не старше момента включения.
- Не удалять существующие карточки и не менять их трёхдневный срок.
- Не создавать дополнительный RTSP-сеанс: остаются основной эфир и объединённый архивный анализатор/кэш.
- Добавить одну чистую проверку временного порога или выделить небольшую политику допуска кадра, если без неё поведение трудно подтвердить.

## 7. Подключить настройки к `AppContainer`

- Создать settings store, storage coordinator и переключаемые хранилища в одном месте при запуске приложения.
- Опубликовать текущие настройки и состояние хранения через `AppContainer` или отдельные наблюдаемые объекты.
- Добавить операцию применения черновика формы: проверить bookmark и папку, сохранить настройки, обновить трекинг и запустить перенос.
- Добавить операцию возврата во внутреннюю папку.
- Вызывать проверку восстановления внешней папки после каждого успешного обновления последних записей, не связывать её с ручной перемоткой.
- Ошибка настройки или миграции не должна переводить `ConnectionState` камеры в ошибку.

## 8. Добавить кнопку и форму настроек

- Создать отдельный `SettingsPopover` или `SettingsPanel`, не добавлять файловую логику непосредственно в `CameraPlayerView`.
- Разместить кнопку-шестерёнку в правом верхнем углу отдельным overlay, симметрично календарю слева и независимо от панели событий.
- Показывать на кнопке небольшой предупреждающий индикатор, когда используется внутренний резерв или перенос ожидает повторения.
- В форме держать черновик: переключатель, отображаемый путь, `Выбрать…`, `Вернуть внутреннюю папку`, состояние, `Сохранить` и `Отмена`.
- Открывать системный `NSOpenPanel` только для выбора папок. Создавать bookmark после подтверждения выбора.
- При отмене не менять действующие настройки. Во время применения блокировать повторное сохранение и показывать спокойный прогресс.
- Использовать только SwiftUI/AppKit API, доступные в macOS 12.

## 9. Проверить регрессии и готовую сборку

- Запустить только новые проверки настроек, выбора корня и миграции, затем существующие важные проверки архива и движения.
- Вручную проверить сохранение/отмену формы, выключение трекинга без прекращения накопления кадров и повторное включение без анализа старого диапазона.
- На временной внешней папке проверить первичный перенос, исчезновение папки, продолжение внутренней записи и обратное объединение после восстановления.
- Убедиться, что календарь, таймлайн, панель событий, масштаб видео и основной эфир визуально не изменились.
- Собрать Debug и Universal Release, проверить `arm64` и `x86_64`, минимальную систему macOS 12, подпись и наличие Core ML-модели.
- Обновить готовую копию `build-release/Build/Products/Release/MiniCam.app` и README с описанием настроек и поведения внешнего диска.
